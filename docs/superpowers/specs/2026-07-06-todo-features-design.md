# TODO Features — Consolidated Design (2026-07-06)

Design record for the five P1/P2 features from TODO.md's Features section,
implemented in parallel worktrees off `ai/main` and merged 2026-07-06
(merge commits `f6e99ac`, `7c0a22b`, `14d274c`, `b2128ac`, `554cfea`).
Approved by the user before implementation (one consolidated review).

## 1. Hyperlink fields in popups/detail panel (P1)

`PropertyDisplaySchema` gains `type: 'text' | 'link'` and optional `linkText`.
Both fields are optional with **no Zod default** — `undefined` semantically
means `text`, so legacy configs round-trip byte-for-byte. The shared
`PropertyList` primitive (used by `FeatureTooltip` and `FeatureDetailPanel`)
renders `<a href target="_blank" rel="noopener noreferrer">` only when the
field is typed `link` **and** the value passes `isSafeHttpUrl()`
(`packages/map-ui-lib/src/utils/propertyDisplay.ts`): string → `new URL()` →
protocol whitelist `http:`/`https:`. Everything else falls back to plain text.
**The whitelist is the single security boundary — do not loosen it.**
PropertyDisplayEditor gains a Type selector and conditional Button-text input;
`fromEntries` omits `type: 'text'` / empty `linkText` (known trade-off:
toggling Link → Text discards entered button text). CSV export and
ResultsDrawer don't consume `propertyDisplay` and were deliberately untouched.

## 2. Highway shields (P1)

Schema and renderers already supported `icon-image` + `text-field` on one
symbol layer (icon draws behind text natively) — the gap was assets.

- **Assets:** 6 generic, trademark-safe shield shapes as **SDF icons**
  (tintable via existing `icon-color`), generated by
  `scripts/shield-sprite/build.mjs` (sharp + potpack; `@mapbox/spritezero`
  rejected — archived, node-mapnik bindings fail on Node 25/darwin-arm64).
  Output checked in byte-identical to `apps/map-client/public/sprites/shields/`
  and `apps/admin-app/public/sprites/shields/` — **regenerate both together**
  via the build script; there is no CI sync check.
- **Injection:** runtime-only via `withDefaultShieldSprite` (spriteUtils) in
  both renderers under sprite id `shields`; never persisted into configs. A
  config-level SpriteSource with id `shields` overrides the default entirely.
- **Editor:** "+ Add road shields" quick action in LayerEditor (sibling of
  "+ Add line labels"), backed by pure `buildRoadShieldsStyle` in
  `utils/stylePresets.ts`. Approved defaults: `icon-color #1a5fb4`,
  `symbol-spacing 300`, `icon-text-fit: 'both'`. The `padding` widget for
  `icon-text-fit-padding` in PropertyField was net-new UI (previously dead
  registry code).
- **Known degradation path:** if the basemap style fetch fails (auth/CORS),
  the raw style URL is used and the default sprite is not injected — shield
  layers render text without the shield.

## 3. Imagery source display-name labeling (P1)

The TODO's premise was partly stale: rename fields already existed in every
editor. Real gaps fixed: `ImageryPanel` and `BasemapSwitcher` rendered
`label` raw with no fallback, and Custom-Basemap add flows seeded blank
labels. Fix: shared `resolveDisplayLabel` (`label || id`, trimmed) in
`utils/labelUtils.ts` applied to the toggle components; six `label: ''`
seeds in SourcesPage now seed `'New Basemap'`; warning-severity blank-label
lint rules in `lintMapConfig.ts` (deliberately not error — legacy configs
with blank labels still save; flip one line to harden).

## 4. Per-style zoom visibility (P2)

Optional `minZoom`/`maxZoom` (0–24) on all four style schemas
(`FillStyleSchema` etc.); min ≤ max enforced in `MapConfigSchema`'s
top-level `superRefine` (a per-style `.superRefine` would break
`z.discriminatedUnion`). Pure `resolveStyleZoomBounds(layer, style)`
(`utils/styleZoomBounds.ts`) intersects layer and style bounds
(max-of-mins / min-of-maxes; 0 is a valid bound) and is spread into
`commonProps` in both renderers, so `dashByCategory`-expanded sub-layers
inherit it. StyleEditor gains two numeric fields (blank = unbounded);
StyleCard shows a `z{min}–{max}` chip. **Accepted gap:** a style range
disjoint from its layer's range validates and silently never renders
(documented in docs/CONFIGURATION.md; candidate follow-up).
`renderStyleLayers` is exported from MapContainer.tsx test-only (enables
the real-render-path inheritance test; costs react-refresh HMR on that file).

## 5. Default label font (P2)

`ui.defaultLabelFont: string[]` (Zod default `['Open Sans Bold']` — bleeds
less with halos), following the `controlLayout` precedent: wizard-editable,
not URL-synced. Resolution at render time via pure `applyDefaultLabelFont`
(`utils/labelFont.ts`) called at both renderers' layout-merge sites: an
explicit per-style `text-font` always wins; symbol styles only. Five
UIConfig-typed literals all carry the field (schema default, ConfigWizardPage
`DEFAULT_UI_CONFIG`, mapStore initial state, map-config.ts, ConfigReview test
fixture). Wizard offers a curated dropdown verified against the CARTO glyph
servers plus free-text custom; picking a stack a basemap's glyph endpoint
doesn't serve falls back silently in MapLibre (inherent, noted in UI copy).
A structural parity test (`MapPreview.labelFont.test.ts`) locks the merged
renderer shape.

## Cross-feature couplings

- Shield text picks up the map default font, and `icon-text-fit` sizes the
  shield from text metrics — changing `defaultLabelFont` resizes shields.
  Intended.
- Zoom and font both rewrote the `commonProps`/layout hunk in
  `renderStyleLayers` (MapContainer) and `renderPreviewStyleLayers`
  (MapPreview); the merged shape is
  `layout: applyDefaultLabelFont({...style.layout, visibility}, style, defaultLabelFont)`
  followed by `...resolveStyleZoomBounds(layer, style)`.
- Merge order used: imagery → hyperlink → zoom → shields → font.
